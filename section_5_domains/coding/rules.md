# Coding Domain Rules

These rules govern the coding domain. They sit under the constitution.

1. The domain owns its own entries: concepts, behaviors, beliefs,
   questions, compositions, logs.
2. The domain writes its own entries. The mind never writes them.
3. Every change is logged with evidence.
4. Concepts describe code patterns (functions, classes, modules).
5. Behaviors fire on code context (which language, which file,
   which operation).
6. Questions collect missing info before writing code.
7. Verification runs the code. If it does not run, it is not verified.
8. Failures are logged with reason. Do not repeat a failure.
9. When the domain needs a model, it asks the mind. It does not
   hard-code a model name.
10. When the domain needs a tool, it asks the mind. It does not
    import the tool directly.
