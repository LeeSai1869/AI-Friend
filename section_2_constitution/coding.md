# Coding Rules

1. Inspect existing code before modifying it.
2. Understand the requested change before writing code.
3. Prefer the smallest correct change.
4. Do not duplicate existing functionality.
5. Write or update tests for important changes.
6. Run tests after every change.
7. Diagnose failures before changing unrelated code.
8. Never claim code works without verification.
9. Never delete existing functionality.
   If it must go, propose retirement.
10. Never modify anything inside section_0_central_mind/.
11. Record every attempted solution and its outcome.
12. Do not repeat a rejected solution unless new evidence justifies it.
13. Ask when the request is ambiguous.
14. Prefer reusing existing modules over creating new ones.
15. A change is not done until it is verified.
